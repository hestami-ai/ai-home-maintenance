## CONSTITUTIONAL CANDIDATES

- "Did the system preserve the essential structure of the human intent as it was recursively transformed into an implemented and verified outcome?" (Fusion Analogy.md L104-108) — The governing question of the whole discipline, replacing "did the model produce a good answer"; intent-structure preservation across transformation is the system's constitutional test.
- "**Compliance** asks whether the current artifact satisfies a particular validator. **Stability** asks whether the artifact remains valid after interacting corrections. **Convergence** asks whether successive states are approaching an acceptable solution. **Confinement** asks whether the complete trajectory remains within the boundaries of acceptable professional work." (Fusion Analogy.md L329-335) — Four distinct assurance properties a mature architecture must separate; passing a check proves only the weakest of them.
- "A workflow can momentarily pass every discrete check and still be unstable." (Fusion Analogy.md L339) — The core anti-vacuity axiom: discrete validation passes never establish system soundness; forbids treating gate-green as done.
- "The objective is not maximum constraint. It is sustained productive confinement." (Fusion Analogy.md L435-437) — Constitutional balance: governance exists to preserve productive generative freedom inside boundaries, not to eliminate it.
- "Intent must remain preserved. Identity must remain coherent. Dependencies must remain satisfiable. State transitions must remain legal. Evidence must support claims. Changes must account for their consequences. Corrections must converge." (Fusion Analogy.md L421-433) — The seven-clause definition of the operating envelope; each clause is an enforceable invariant class.
- "when the system must stop rather than continue correcting." (Fusion Analogy.md L159) — Governance must include a mandatory-halt condition; endless remediation is itself an envelope violation.

## DOCTRINE-CONOP

- "Prompt engineering shapes an invocation. Context engineering shapes the information available to the model. Loop engineering shapes the iterative interaction ... Shape Engineering is the discipline of engineering that complete transformation." (Fusion Analogy.md L70-100) — Positions the harness discipline as the fourth, largest scope: the whole intent-to-verified-outcome transformation.
- "a legal analysis, engineering design, medical assessment, financial investigation, or systems architecture is not merely a sequence of prompts. It is a trajectory through a structured problem space." (Fusion Analogy.md L78) — Professional work is a trajectory, so control must act on trajectories, not on isolated outputs.
- "Each transformation changes the shape of the work. And each transformation creates opportunities for drift, distortion, information loss, invalid inference, and local optimization." (Fusion Analogy.md L96-98) — Why validators attach at transformation boundaries: each transformation is a distinct risk-injection point.
- "Their implementation form is independent criticism. Their system function is confinement." (Fusion Analogy.md L137-138) — Validators are independently executed critics, but their purpose is coordinated trajectory control, not standalone QA scoring.
- "a collection of AI critics is not automatically a validation architecture. The larger control structure matters" [which validators per phase, observable state, finding classification, remediation, revalidation, conflict resolution, convergence, advance/stop] (Fusion Analogy.md L146-163) — Architecture is the placement-and-response topology, not the critic count; enumerates ten design dimensions.
- "The work is decomposed into phases and sub-phases. Each phase has a purpose. Each transformation has expected inputs and outputs. Relevant validators are configured at the point where their concerns become meaningful." (Fusion Analogy.md L175-181) — The workflow itself creates the confinement geometry; the harness "gives professional work a controlled topology" (L193).
- "There is no single universal validator capable of determining whether a complex agentic trajectory remains sound. Different forms of instability require different forms of detection and corrective force." (Fusion Analogy.md L213-215) — Grounds the multi-validator taxonomy: intent, scope, identity, state, dependency, design-rationale, change-impact, second-order-effects, evidence, convergence (L217-235).
- "What combination of constraints must be active at this particular transformation boundary to keep the work inside its acceptable operating envelope?" (Fusion Analogy.md L245) — The per-boundary validator-selection question; validator configuration is a design decision per transformation, not a global default.
- "The agent naturally experiences the local problem. The validation system must represent the neighborhood." [rationale, dependencies, invariants, consumers, historical decisions, state transitions, second-order effects] (Fusion Analogy.md L295-299) — Division of cognitive labor: agents see locally, validators must carry the system-wide context the agent cannot.
- "future validator systems will need to reason not only about artifacts, but about trajectories. The history of the work matters." (Fusion Analogy.md L345-347) — Validation's object evolves from current output to "the shape of the evolving work" (L359-361).
- "Observability is therefore not merely an operational concern. It is part of the control architecture. Without diagnostics, validators see isolated artifacts. With diagnostics, they can reason about trajectories." (Fusion Analogy.md L388-394) — Observability is a functional precondition of trajectory-level validation, not ops hygiene.
- "The scarce capability may therefore become the ability to confine generative intelligence into reliable professional trajectories." (Fusion Analogy.md L471) — Strategic thesis: intelligence abundant, confinement scarce; justifies investing in harness over model.

## SEMANTIC-INVARIANTS

- "A more powerful model can reason across more possibilities ... But the same increase in capability also expands the space of possible deviations." (Fusion Analogy.md L47) — Capability and deviation-space grow together; governance need increases, never decreases, with model quality ("A hotter plasma ... makes confinement more consequential", L60-62).
- "a language model is not the complete professional system. It is a generative cognitive medium inside a larger engineered structure." (Fusion Analogy.md L43) — The model-is-not-the-machine invariant; system properties belong to the harness, not the model.
- Failure taxonomy of capable agents: "substitute a nearby objective for the actual objective; lose the identity of entities across a long workflow; simplify away information whose downstream purpose it does not understand; repair one defect while introducing another; produce highly plausible work that is structurally wrong; continue confidently after leaving the intended trajectory." (Fusion Analogy.md L49-58) — The canonical deviation catalog every validator class maps back to.
- "Every individual correction may be locally reasonable. Every validator may be functioning correctly. But the overall system is oscillating." (Fusion Analogy.md L321-325) — Oscillation invariant: component-level correctness does not compose into system stability; convergence must be measured, not assumed.
- "A remediation loop can continue indefinitely without converging." (Fusion Analogy.md L343) — Remediation is not self-terminating; convergence detection (correction magnitude decreasing, findings migrating, defects recurring — L349-357) is a required capability.
- "The right question is often not: Does this local change work? It is: If you do that, how do you expect this all to work?" (Fusion Analogy.md L269-275) — The system-continuity test that complements Chesterton's Fence: ask both why a structure exists and whether the surroundings survive its change (L289-293).
- "an AI system constrained to deterministic behavior at every point would lose much of the value of generative intelligence. The engineering problem is to preserve productive freedom inside controlled boundaries." (Fusion Analogy.md L404-406) — Over-constraint is a failure mode symmetric to under-constraint.
- Local-optimization degradation pattern: "A complex object becomes a list of IDs. A rich relationship becomes a string. An explicit state becomes a null check. A structured requirement becomes a summary." (Fusion Analogy.md L256-262) — Concrete signature of information-loss drift; each substitution silently destroys downstream-consumed structure.

## PROTOCOL-PRACTICE

- "Every core workflow phase and sub-phase is individually validated by the validators configured for that point in the workflow. The validators are selected because particular transformations create particular risks." (Fusion Analogy.md L126-128) — Per-phase validator configuration keyed to transformation-specific risk; not a uniform validator suite.
- "Their findings feed remediation. Remediation is re-evaluated. The system determines whether the work has converged sufficiently to continue." (Fusion Analogy.md L129-133) — The findings→remediation→revalidation→convergence-gate loop as the standard control cycle.
- Trajectory diagnostics to observe: "state transitions; identity creation and propagation; requirement transformations; decisions and their rationale; tool interactions; validation findings; remediation attempts; repeated failures; downstream blocking; convergence behavior." (Fusion Analogy.md L377-386) — The ten-item observability checklist; "logging prompts and responses" is explicitly insufficient (L396).
- Before allowing simplification/removal, ask: "What information was previously carried by this structure? Who consumes it downstream? Which assumptions depend upon it? What becomes impossible to reconstruct? What behavior changes three workflow stages later?" (Fusion Analogy.md L277-287) — The change-impact interrogation protocol for any structure-reducing edit.
- Convergence-monitoring questions: "Which defects keep returning? Which validators repeatedly trigger after another validator's recommendation is applied? Is the magnitude of correction decreasing? Are findings migrating through the system?" (Fusion Analogy.md L349-355) — Operational signals distinguishing convergence from oscillation among failure forms.
