## DOCTRINE-CONOP

- "Avoid relying primarily on UI snapshot tests for semantic correctness. The canonical domain behavior must be tested below the UI." (RPH-DOC-008.md L249-251) — Semantic truth lives in the domain layer; UI evidence is never proxy for domain conformance.
- "Tests should assert more than final state. Where applicable, assert: returned command status; error code; aggregate revision; semantic version; emitted event types; ... created trace links; affected projections; outbox messages; absence of prohibited side effects." (RPH-DOC-008.md L219-233) — Conformance means whole-behavior assertion, including that prohibited side effects did NOT happen.
- "The test suite is organized into seven layers." [schema, domain invariant, state-transition, property-based, persistence/replay, service integration, end-to-end] (RPH-DOC-008.md L95-163) — Layered proof strategy: from structural validity up to complete professional scenarios intent-through-baseline-promotion.
- "The initial suite does not fully cover: unrestricted dynamic planning; distributed execution; multi-tenant SaaS isolation; arbitrary professional ontologies; marketplace-imported policies; numerical confidence aggregation; full implementation and release baselines; production deployment." (RPH-DOC-008.md L80-91) — Explicit deferral list; conformance claims are scoped to the intent-to-architecture vertical slice.
- "the controller must not issue a fourth retry. It must select: change tactic; replan; escalate; reject; abandon." (RPH-DOC-008.md L1154-1174) — RPH-EXE-008: retry budgets are hard; exhaustion forces an enumerated control decision, never silent looping.

## SEMANTIC-INVARIANTS

- "originating expression is preserved exactly; no formalized objective is inferred automatically." (RPH-DOC-008.md L423-441) — RPH-INT-001: raw intent is captured verbatim; formalization is a later, explicit act, never inference.
- "The approval decision references version 3. If version 4 is later created, the version-3 approval does not authorize version 4." (RPH-DOC-008.md L504-518) — RPH-INT-005: human authority binds to a semantic version; approvals never float forward. Superseded intents likewise cannot authorize new work (L543-555).
- "semantic version increments; `IntentRevised` is emitted; impact analysis is requested; affected descendants are classified; the prior baseline remains immutable; prior approvals are marked review-required where applicable." (RPH-DOC-008.md L522-539) — RPH-INT-006: material intent revision cascades review downstream while history stays immutable. Approval also requires desired outcomes exist (L484-500).
- "state is `PROPOSED`; execution state is `NOT_PLANNED`; assurance state is `UNASSESSED`; shape integrity is `UNKNOWN`" (RPH-DOC-008.md L561-577) — RPH-PWU-001: PWU birth initializes lifecycle, execution, assurance, and shape as orthogonal axes, each starting unknown/unassessed.
- "execution succeeded; required evidence is admitted; all mandatory assurance assessments are satisfied. ... the PWU may transition to `SATISFIED`." (RPH-DOC-008.md L640-654) — RPH-PWU-006: satisfaction requires the full triad — execution, admitted evidence, satisfied mandatory assurance; and any REJECTED assessment blocks it (L658-670).
- "A PWU in `BASELINED`. ... new execution is requested against the same semantic version. ... the command is rejected. A successor revision or successor PWU is required." (RPH-DOC-008.md L706-720) — RPH-PWU-010: baselined state is immutable-in-place; change happens only through successors.
- "finding `MISSING_OBLIGATION_ALLOCATION` is emitted; decomposition is `INVALID`; child execution is blocked." (RPH-DOC-008.md L754-768) — RPH-DEC-002: an unallocated mandatory obligation invalidates the decomposition AND blocks children from executing; a silently dropped constraint likewise rejects the decomposition (L772-784).
- "a child PWU introduces national-enterprise workforce optimization without authorization. ... `CHILD_INTENT_DIVERGENCE` is emitted; decomposition is rejected or requires human decision." (RPH-DOC-008.md L788-801) — RPH-DEC-004: children cannot enlarge scope beyond parent intent without human authority — anti-scope-drift.
- "all child PWUs are individually satisfied. ... their artifacts use incompatible tenant-identity models. ... parent is not satisfied; recomposition state becomes `CONFLICTED`" (RPH-DOC-008.md L821-839) — RPH-DEC-006: child satisfaction does not sum to parent satisfaction; recomposition is a separate judged act, and a recomposition contract is mandatory (L805-817).
- "the assessment completes without creating an Assumption Object. ... the assessment result is rejected or remains incomplete." (RPH-DOC-008.md L953-965) — RPH-ASM-002: material assumptions must become first-class objects; prose-only disclosure fails assessment. Human acceptance yields `ACCEPTED`, never `VERIFIED` (L969-977).
- "status becomes `FALSIFIED`; ... impact analysis is required; affected PWUs become `AT_RISK`, `RESHAPING_REQUIRED`, or `INVALIDATED`; dependent claims are reviewed." (RPH-DOC-008.md L981-997) — RPH-ASM-004: falsification propagates through everything the assumption supported; and unresolved critical assumptions block irreversible steps absent verification or authorized acceptance (L1001-1016).
- "a runtime binding requesting file-system and network access. ... only file-system access is granted. ... network operations fail authorization." (RPH-DOC-008.md L1090-1102) — RPH-EXE-004: requested capability is never granted capability; enforcement at operation time. Execution cannot start on a merely REQUESTED binding (L1070-1086).
- "the statement must become or reference a Claim Object before assurance can evaluate it." (RPH-DOC-008.md L1195-1203) — RPH-EVD-001: agent assertions of completion are inert until reified as governed Claims; a claim with no admissible evidence cannot become SUPPORTED (L1207-1219).
- "dependent claims become contested or under assessment; dependent assessment becomes invalidated or review-required; baseline readiness is recalculated." (RPH-DOC-008.md L1251-1265) — RPH-EVD-005: evidence invalidation propagates transitively to claims, assessments, and baseline readiness — no stale support survives.
- "both remain attached. The system cannot silently discard the contradicting evidence." (RPH-DOC-008.md L1269-1279) — RPH-EVD-006: contradictory evidence is preserved and visible; the record never self-curates toward support.
- "A validator result includes only four criterion results. ... The Assurance Service rejects the result" (RPH-DOC-008.md L321-337) — RPH-CON-005: partial validator output is invalid output — every mandatory criterion must be answered; results for the wrong policy version or wrong subject semantic version are likewise rejected (L341-377), preventing stale assessments approving changed objects.
- "a `pwuKind` string alone is insufficient to establish either binding." (RPH-DOC-008.md L402-417) — RPH-CON-009: type identity is resolved binding to a versioned PWA (or declared local extension), never a bare kind label.
