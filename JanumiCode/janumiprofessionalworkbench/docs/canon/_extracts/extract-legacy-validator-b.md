## CONSTITUTIONAL CANDIDATES

- "A compiled heuristic may appear more authoritative because it has been formalized. The system must preserve epistemic status and provenance." (Janumicode_v2 - Validator Subsystem.md L1273-1275) — Formalization must not launder uncertain wisdom into false authority; provenance is constitutional.
- "If all validators share the same model, assumptions, and evidence, apparent independence may be illusory. Diversity must be structural, not merely nominal." (Janumicode_v2 - Validator Subsystem.md L1279-1281) — Anti-monoculture rule: validator independence must be architecturally real, echoing INV-5 exec≠assurance.
- "Agents may learn to produce artifacts that satisfy validator-visible proxies without satisfying underlying intent. Validators themselves therefore require proxy-integrity review." (Janumicode_v2 - Validator Subsystem.md L1285-1287) — Anti-Goodhart: the assurance layer itself is a governed, reviewable object.
- "Established doctrine can become obsolete. Controls require versioning, challenge, and retirement." (Janumicode_v2 - Validator Subsystem.md L1291-1293) — Wisdom is not frozen; every control carries a lifecycle including retirement.
- "Professional principles frequently conflict. The system must expose tradeoffs rather than hiding them." (Janumicode_v2 - Validator Subsystem.md L1297-1299) — Conflicting doctrine is surfaced to judgment, never silently resolved.
- "Passing all validators does not prove correctness. The system should communicate residual uncertainty." (Janumicode_v2 - Validator Subsystem.md L1303-1305) — Compliance ≠ correctness; residual-risk honesty is a system obligation.
- "The accumulated wisdom of a profession should not merely inform an agent. It should shape the work, constrain the transformation, challenge the output, govern the correction loop, and determine what evidence is required before the result is trusted." (Janumicode_v2 - Validator Subsystem.md L1529) — The document's central premise; candidate charter language for the assurance layer.
- "The resulting architecture is not a better prompt. It is a professional control system." (Janumicode_v2 - Validator Subsystem.md L1523-1525) — Identity claim distinguishing governed control from prompt engineering.
- "**Convert validator output from transient advice into governed obligations with lifecycle state.**" (Janumicode_v2 - Validator Subsystem.md L2478) — Named "the most important remediation"; findings are durable obligations, not advice.
- "No validator finding should disappear merely because the artifact was regenerated. That is the core implementation move." (Janumicode_v2 - Validator Subsystem.md L2500-2502) — Finding persistence across regeneration is the load-bearing invariant of convergence.
- "Human override should not erase findings. It should create: human_risk_acceptance_record" (Janumicode_v2 - Validator Subsystem.md L2270-2274) — Override is recorded risk acceptance, never deletion of evidence.
- "Gate Health validators should not block human decisions... Gate Health should emit telemetry and review flags, not hard blocks." (Janumicode_v2 - Validator Subsystem.md L2019) — Human authority sits above the assurance system; meta-validators observe, never veto humans.
- "Any repair that changes identifiers, parent-child relationships, references, trace links, or entity semantics must rerun the **full Entity Integrity family**." (Janumicode_v2 - Validator Subsystem.md L1974-1976) — Declared "non-negotiable rule"; identity-touching repairs always trigger full identity revalidation.
- "If a canary passes undetected, the finding is against the validator system" (Janumicode_v2 - Validator Subsystem.md L2216) — Meta-validation rule: undetected corruption indicts the assurance layer itself, at CRITICAL severity.

## DOCTRINE-CONOP

- "**Do not introduce a new convergence subsystem until the existing validation, repair, gate, and stream mechanisms have been mapped, reused, or deliberately superseded.**" (Janumicode_v2 - Validator Subsystem.md L1550) — Roadmap principle: reconcile-then-extend, forbidding duplicate subsystems.
- "So the first task is not implementation. It is **implementation archaeology**." (Janumicode_v2 - Validator Subsystem.md L1574) — Phase 0 is a codebase reconciliation audit; named method for legacy-aware design.
- "findings should be able to indict not only artifacts, but also the generation process, validator system, repair process, or gate." (Janumicode_v2 - Validator Subsystem.md L1716) — Widened target model: assurance covers process and the assurance machinery, not just outputs.
- "Phase binding answers: Where are we in JanumiCode's workflow? Stage binding answers: Where are we in the generation lifecycle?" (Janumicode_v2 - Validator Subsystem.md L1744-1750) — Two orthogonal binding axes for validation events; stage added as metadata, not an engine rewrite.
- "Dropping a blocking convergence controller into the middle could destabilize the workflow. Start by recording convergence state without enforcing it." (Janumicode_v2 - Validator Subsystem.md L1803-1805) — Observe-mode-first doctrine for introducing any new enforcement.
- "add deterministic IDs... This prevents findings from 'disappearing' across retries because the text changed slightly." (Janumicode_v2 - Validator Subsystem.md L1852-1858) — Semantic rule behind finding identity: content-derived stability across retries.
- "Running every validator every time is expensive. Running too few validators misses regressions." (Janumicode_v2 - Validator Subsystem.md L1932-1934) — Rationale for targeted revalidation: revalidation set selected by diff surface intersecting inspection surface.
- "Prevent superficial fixes such as regex-only patches for semantic identity failures." with policy "FailureMode → AllowedRepairStrategies" (Janumicode_v2 - Validator Subsystem.md L2042-2048) — Root-cause repair doctrine: each failure mode disallows shallow repairs and mandates adequate ones.
- "deterministic failure-mode routing + rule-based repair strategy constraints + LLM validator only when semantic judgment is needed" (Janumicode_v2 - Validator Subsystem.md L2079-2083) — Hybrid-check doctrine: escalate to model calls only where determinism cannot judge.
- Identity resolution hierarchy: "1. Exact canonical ID match 2. Deterministic alias table match 3. Normalized lexical match 4. Embedding candidate retrieval 5. LLM semantic equivalence judge 6. Human escalation" (Janumicode_v2 - Validator Subsystem.md L2114-2121) — Ordered escalation ladder from deterministic to human for identity convergence.
- "Do not implement the full Process Validator branch at once. Start with the highest-leverage validators" (Janumicode_v2 - Validator Subsystem.md L2162) — Prioritize process validators that catch failures before expensive downstream reasoning (context, registry, injection, parse).
- "Unresolved CRITICAL findings block Phase Gate eligibility... Only after that should LLM-judge BLOCK findings become hard blockers." (Janumicode_v2 - Validator Subsystem.md L2459-2468) — Enforcement rollout order: CRITICAL first, deterministic BLOCK second, LLM-judge blocks last.
- "The risk is not that JanumiCode lacks validation. The risk is that validation outcomes are not yet treated as durable obligations." (Janumicode_v2 - Validator Subsystem.md L2474) — Diagnosis framing the entire roadmap: the gap is obligation lifecycle, not validator count.
- "The ultimate measure is not: Did the agent comply with the rules? It is: Did accumulated professional knowledge measurably improve the reliability of professional work?" (Janumicode_v2 - Validator Subsystem.md L1422-1428) — Evaluation doctrine: outcome reliability over rule compliance; anchors the ten evaluation measures.
- "**Professional knowledge → executable controls → governed work → evidence-backed trust**" (Janumicode_v2 - Validator Subsystem.md L1442) — Strategic value chain replacing "better model → better prompt → more tools → better output".

## VOCABULARY

- Finding lifecycle: "OPEN → ASSIGNED_TO_REPAIR_PLAN → REPAIR_ATTEMPTED → REVALIDATION_PENDING → RESOLVED" or "HUMAN_ACCEPTED_RISK, DEFERRED_WITH_RATIONALE, SUPERSEDED_BY_STRONGER_FINDING, ESCALATED_TO_HUMAN, ROLLBACK_REQUIRED" (Janumicode_v2 - Validator Subsystem.md L2482-2498) — The obligation lifecycle: every terminal state is an accountable disposition, none is silent disappearance.
- Gate actions with convergence meanings: "APPROVE — Accept artifact and resolved finding set; REJECT...; OVERRIDE — Accept known residual risk; REFRAME — Change governing intent/scope/constraint" (Janumicode_v2 - Validator Subsystem.md L2261-2266) — Reuses existing gate vocabulary but assigns convergence semantics; OVERRIDE ≡ risk acceptance, REFRAME ≡ intent change.

## SEMANTIC-INVARIANTS

- "A phase or sub-phase cannot proceed to the human Phase Gate unless: 1. No unresolved CRITICAL finding... 3. WARN findings are resolved, accepted, or explicitly deferred. 4. No repair introduced a new BLOCK or CRITICAL finding..." (Janumicode_v2 - Validator Subsystem.md L2003-2015) — Gate convergence invariant, including repair-regression check and entity/traceability consistency preconditions.
- "A repaired artifact cannot converge if it references: missing entities, duplicate identities, ambiguous identities, orphaned child nodes, collided identifiers, silently mutated entity meanings" (Janumicode_v2 - Validator Subsystem.md L2140-2150) — Identity integrity as a convergence precondition, not a separate advisory check.
- "Every nontrivial retry or repair has: triggering finding, repair strategy, before/after artifact identity, diff scope, revalidation set" (Janumicode_v2 - Validator Subsystem.md L1914-1922) — Repair accountability invariant: no untraced repair; makes repair regression tractable.
