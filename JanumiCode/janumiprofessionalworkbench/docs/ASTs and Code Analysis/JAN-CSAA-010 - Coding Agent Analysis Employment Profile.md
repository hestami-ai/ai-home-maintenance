## 1. Purpose and protected question

This profile specializes the general agent procedure only where a coding agent consumes Codebase Semantic Analysis and Assurance capabilities. It turns the adopted employment allocation into a precise, testable procedure while leaving every semantic object, analysis capability, rule, finding, gate, fixture, shape, conformance method, operational behavior, and provider qualification with its existing concern owner.

The protected question is:

> At each material software-engineering employment point, what exact analysis and evidence must a coding agent obtain, how must it bind and cite that evidence, what must change in its plan, when must it reanalyze, stop, or escalate, and what may it truthfully claim at handoff?

The answer is an employment contract, not an analyzer implementation. Invocation and positive-result verbs are conditional on the separately authorized profiles, qualified providers, executable artifacts, and bound subject they depend on; absence handling is controlled by `CSAA-010-DUT-010`, `CSAA-010-PRO-008`, `CSAA-010-STP-001`, `CSAA-010-STP-006`, `CSAA-010-STP-010`, and `CSAA-010-STP-011`.

## 5. Risk, profile selection, and cheapest-relevant-proof ordering

The coding agent first names the affected concern and consequence of an unsound answer. It then resolves the exact authorized Analysis Rule Profiles and Repository Gate Profiles that apply. This profile does not invent default profiles, severities, thresholds, or gate semantics.

| Employment risk signal | Mandatory widening |
| --- | --- |
| Public API, schema, serialization, or compatibility boundary | Type/symbol/contract analysis, callers and consumers, compatibility evidence, affected tests, and governed contract gates |
| Package, module, architecture, or dependency boundary | Dependency and call closure, architecture rules, before/after coupling evidence, exceptions, and integration gates |
| Control-flow, data-flow, authorization, confidentiality, or security boundary | CFG/DFG/taint/boundary analysis, threat evidence, negative paths, dependency intelligence, and adversarial evidence |
| Dynamic entry, reflection, framework registration, dependency injection, serialization, plugin, or generated dispatch | Dynamic-entry model, runtime/test corroboration, unresolved coverage, and conservative candidate wording |
| Persistence, migration, recovery, concurrency, cancellation, or operational health | Exact operational profile, failure/recovery evidence, compatibility and rollback, and degraded-state accounting |
| Generated or virtual source boundary | Generator/input/configuration identity, source-origin mapping, generated-context freshness, and consumer impact |
| Test, fixture, coverage, mutation, trace, or oracle change | Oracle integrity, subject/denominator/instrumentation identity, tests-of-the-tests, mutation or differential evidence, and independent expected judgment |
| Target-branch or cross-branch change | Candidate-merge subject, recomputed closure, target configuration, integration and regression gates |

Cheapest-relevant-proof means start with the least costly evidence capable of deciding the exact question, then widen when its coverage, epistemic strength, freshness, or agreement is insufficient. It never means choosing a cheap tool that cannot establish the predicate, omitting a mandatory profile, weakening an oracle, or letting budget convert unknown into green.

## 6. Query, citation, and evidence-use contract

A coding agent consumes semantic evidence only through an exact subject-bound result or reconstructable record. A citation records what was asked, which subject and configurations were used, what capability/provider/method produced the result, what coverage and health applied, whether the fact was direct or derived, which raw provenance supports it, what was excluded, and which conclusion or plan decision consumes it.

Negative evidence receives stricter treatment: “no callers,” “no finding,” “unchanged coverage,” “no dependency,” and “no trace” are bounded statements about a declared search and evidence set. They are never universal absence claims. A successful empty result requires positive population and coverage evidence; otherwise the state is inconclusive, unsupported, stale, failed, or partial rather than clean.

## 13. Findings, disagreement, and plan change

A finding is an input to the work plan, not a nuisance to suppress. On receipt or change, the coding agent records the exact affected work and claim, applies the rule/gate outcome owned by `JAN-CSAA-004`, and chooses only among: remediate and reverify; stop the dependent action; continue an evidenced unaffected scope; or rely on an exact externally authorized disposition. The agent does not create a fifth path by silence.

Provider disagreement remains two attributed observations until exact concern-owner semantics or authorized adjudication resolve it. Majority vote, provider precedence invented locally, normalization loss, or choosing the desired result is prohibited.

---

## 14. Reanalysis triggers

Reanalysis is conclusion-driven, not file-count-driven. A trigger invalidates every conclusion whose subject, configuration, dependency closure, method, oracle, profile, provider, evidence set, or health basis it changes. The agent reconstructs a coherent successor or reports the result partial/noncurrent; it never publishes a mixed-revision answer as current.

## 16. Exception employment

An exception changes only the exact predicate and scope its recognized authority owns. The underlying failed or violated evidence remains. The agent verifies the exception identity, subject, scope, issuer, time, expiry, residual risk, and applicability before use; it then cites the exception everywhere it affects planning, gating, completion, and handoff. No configuration, absence, comment, prior practice, user convenience, or agent assertion is an exception.

---

## 17. Completion and handoff contract

Before completion, the coding agent closes the applicable work-package ledger and reports the exact final subject, target-merge state, analyses and gates actually run, evidence-priority account, capability coverage, currentness, provider health and limitations, tests and inspected outcomes, findings and dispositions, exceptions, changed contracts/configuration/generated boundaries, compatibility and rollback, residual risk, unresolved decisions, unverified areas, and any governance entries. “Done” is prohibited when an applicable ledger row is concealed or a required check did not support its claimed state.
