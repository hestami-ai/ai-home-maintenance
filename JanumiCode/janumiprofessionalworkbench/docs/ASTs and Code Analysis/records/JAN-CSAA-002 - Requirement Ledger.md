## 3. Row-contract defaults

These defaults complete every compact row unless §3.1 or the row itself states otherwise:

- Owner/source is the exact controlled artifact shown; local rows are owned by JAN-CSAA-002.
- Applicability and disposition are `APPLICABLE_NOW` for the current documentation-only Draft under `REG-D-018` as extended by `REG-D-021` and corrected by `REG-D-022`; the explicit exception overlay preserves post-ledger-self-review, later-lifecycle, later-execution, deferred, successor-controlled, and not-applicable states.
- Disposition authority is the exact source plus the registered overlay named in §3.1; a compact row never invents a waiver or authority.
- The fulfillment cell is the planned design/documentation site. `PLANNED` records candidate text awaiting author-side objective verification; it does not claim that the obligation is implemented.
- The enforced-reference-artifact field is `None; documentation-only Draft` unless a row explicitly names an external exact-shape owner; no executable artifact is claimed, and machine shape remains with JAN-CSAA-007 or a separately adopted reference artifact.
- Current Draft closure verification is `NOT_RUN` and owned by the author/ledger closer against objective row evidence. In every compact requirement table, the value after the final slash is the row's single verification state. Every preceding Verification ID is a required method binding. Method execution state is recorded only in §7 and is not encoded after each ID. Row verification state and method execution state are distinct: a non-current row may remain `NOT_REQUIRED_CURRENT_PHASE` while a current disposition/allocation-check method remains `NOT_RUN` or later becomes `PASSED`. Such a method pass validates only the disposition or allocation; it does not perform or pass the allocated obligation. This activity neither constitutes author self-review nor substitutes for later independent adversarial review or integrity/provenance validation.
- Oracle owner/status is `Author/ledger closer; objective documentation check; no executable oracle change` for current rows. A non-current overlay names its later role and remains `NOT_REQUIRED_CURRENT_PHASE`.
- Later-lifecycle, successor-controlled, and deferred rows use `NOT_REQUIRED_CURRENT_PHASE` where §3.1 or the row says so; no such state means `PASSED`.
- Evidence is the linked Draft, ledger, exact governed sources, and any named objective record.
- Notes are empty unless the row or §3.1 overlay supplies an explicit note or current meaning; an empty note carries no inference.
- No intermediate sponsor disposition is required or present. The final exact-corpus package will provide individual member/material-fork response fields, and each accepted member will receive a distinct exact-member register decision in one transaction.
