## 1. Two corrections to the design, from the mechanics pass

⛔ **DESIGN §6 ITEM 4 IS MIS-SHAPED, AND THE SHAPE MATTERS FOR WHAT GETS RATIFIED.** It asks *"whether workspace
content is PER-8 participating material."* **PER-8 classifies per OBJECT by a PAST-TENSE ACT**, not per content
kind. So the ratifiable question is not *"are workspace files participating material"* but *"which object, having
done what, carries this content."* Reshaped in §10.

⛔ **`Workspace.purge` CANNOT MIRROR `ArtifactStore.purge` EXACTLY, AND I ASSERTED IT COULD.** The store's
purgeability class **is part of the storage key** —
`` `${input.tenantPrefix}/${input.purgeability}/${contentHash.slice(7)}` `` — which is how one flat key space
keeps retention legible. **A workspace is path-named, not content-addressed, so it cannot carry the class in its
address.** The mirror is therefore partial by construction: same `purge(address) → PurgeOutcome` signature, same
tombstone rule, and a *declared* rather than *addressed* purgeability. That difference is designed in §3, not
assumed away.

⭑ What DOES carry over verbatim, and must: `purge` takes one argument and no actor, clock or reason
(`ports/artifact-store.ts:107`); the semantics are **"Remove the BYTES and keep the ENTRY"**, because
*"an `ARTIFACT` record referencing a purged key must stay EXPLICABLE"*; and `Purgeability` has exactly two
members and is **"DELIBERATELY NOT A RETENTION CLASS"** (`REG-Q-056` is OPEN). ⛔ **Do not coin a third member
and do not add a retention class here.**

## 2. Phase 0 · ⛔ NOT LANDED — BLOCKED ON A RULING. Two ratified obligations pull apart

⚠ **THIS SECTION IS CORRECTED FROM ITS FIRST DRAFT.** I wrote it as *"one line, and a short recording"*. Reading
the ratified field and the capture machinery before touching anything showed it was neither.

**WHAT IS ACTUALLY TRUE.** `captureTry` already performs Guide §9.7's lawful split, correctly and completely: it
locates the answer span, retains it `RETAINED_BY_PARTICIPATION`, retains volunteered reasoning
`PURGEABLE_AT_EXPIRY`, deliberately does **not** store the mixed blob, and records `omittedRegions` with the byte
offset so the two reassemble losslessly (`REG-D-056` / `REG-D-057`).

⛔ **THAT MACHINERY NEVER RAN FOR AN EXECUTION STEP.** `run-model-step.ts` handed it a value already reduced
twice — `answer = returned.answerText` strips the reasoning, then `splitExecutionEnvelope` unwraps the envelope —
so the split found nothing to separate and the record took the *"nothing to separate"* branch. **It then asserted
two false things:** that the whole output IS the answer, and — in `volunteeredReasoningRef`'s own words — that
this was *"an observed absence, not an unretained presence."* ⭐ **The reasoning had arrived; the step discarded it
before the recorder could see it. A record that manufactures the absence it then discloses is the shape this
register keeps catching** (cf. `feedback_absence_of_evidence`: a claim about my search dressed as a claim about
the world).

**AND THE SPIKE'S SUGGESTED FIX WAS RIGHT, AGAINST MY OWN DOUBT.** I nearly narrowed it to "record the envelope",
because `model-exchange.ts` refuses `rawOutputBeforeCoercionRef` STORED while `volunteeredReasoningRef` is STORED.
That refusal is not triggered: when the spans separate, `captureTry` sets the whole-blob ref to PENDING with the
§9.7 reason. Passing the true whole reply is exactly what lets the lawful separation run.

**THE FIX WAS BUILT AND PROVED BOTH WAYS — `26 passed` with it, `1 failed | 25 passed` without it, production
restored byte-identical by inversion — AND THEN WITHDRAWN.** ⛔ **It reddens a different ratified invariant, in
e2e, which the unit suite cannot see:**

```
Error: the artifact and the exchange must name ONE stored object
  expected tnt-local/RETAINED_BY_PARTICIPATION/4ece133d…   (answerSpanRef)
  received tnt-local/RETAINED_BY_PARTICIPATION/8044c907…   (the ARTIFACT)
```

With the raw reply, `splitAnswerSpan` locates the JSON **envelope**, so `answerSpanRef` names the envelope while
the ARTIFACT names `envelope.workProduct`. Different bytes ⇒ different content hash ⇒ two objects where
`REG-F-345` requires one, *"and a reader cannot tell which the assessment rested on."*

⭐ **THE DECIDING QUESTION IS A RULING, NOT A BUG: for an execution step, is E-2's ANSWER HALF the WORK PRODUCT or
the harness ENVELOPE that carries it?** The step's own comment says the envelope is *"unwrapped and then
forgotten"* — but the envelope also carries `rationale`, so retaining it whole classifies reasoning as
participating (PER-8, permanent) when PER-12 wants it purgeable. Filed as §10 item 7.

⛔ **AND THE E2E ASSERTION WAS NOT TOUCHED.** It pins a real invariant; editing a test to admit my change is the
one move this programme never makes. The production line is reverted, the defect is **disclosed in place** in
`run-model-step.ts`, and the test that pins it is kept as `it.skip` with the ruling named — the repository's own
idiom for a test blocked on a ratification gap. ⚠ **Deleting it would delete the only statement that the record
currently discloses an absence that never happened.**

⭑ **WHAT THE ATTEMPT IS WORTH ANYWAY.** The defect is now measured rather than suspected, the remedy is known to
work, and the blocker is a named question rather than a mystery. ⭐ **And it is exactly what the spike said it
could not tell me:** it reported *"THE PLAYWRIGHT E2E SUITE WAS NOT RUN. Its status against these changes is
unknown"* — the one place it declined to assume green is the one place the regression was.

**RULE 2:** read by every consumer of `MODEL_EXCHANGE`, by retention, and by any future replay. **If wrong:** the
governed record discloses an absence that never happened, and a replay reproduces a different run — invisibly,
because both runs are green.

⚠ **A NOTE ON THE FIRST RED, WHICH WAS INVALID:** the initial fixture used undelimited prose, which §9.7
deliberately blocks (this suite already pins that at *"an UNDELIMITED prose answer is NOT retained"*), so every
ref was refused and the test would have reddened forever for the wrong reason. The fixture now carries a
locatable answer span.

## 3. Phase 1 · The two ports, and defaults that cannot fabricate

**DO:** `packages/rph-ports/src/ports/workspace.ts` and `process-runner.ts`, plus in-memory / refusing defaults.

- ⛔ **IMPORT `Purgeability` and `PurgeOutcome` from `./artifact-store.js`; do not redeclare them.** The barrel
  already does `export * from './ports/artifact-store.js'`, so a second `export *` is a duplicate-export
  conflict — and a second two-member union is exactly the drift `artifact-store-contract.ts` exists to prevent.
- `Workspace`: `writeFile` · `readFile` · `list` · `purge(path) → PurgeOutcome` · `ownerKind` ·
  `materialization` · `directoryPath?` · exported containment predicate. Purgeability is **declared on the
  workspace**, not encoded in the path (§1).
- `ProcessRunner`: `{argv, cwd, timeoutMs}` → a **union** outcome. `ran: false` is its own arm; `timedOut` is its
  own field, never inferred from the exit code (§36.2 separates TIMEOUT from TOOL_FAILURE, and a SIGKILLed
  process reports `null` on Windows).
- `materialization` exists so a REAL runner wired against an IN_MEMORY workspace is caught **before anything
  runs** — the one failure this seam must never have.

**RULE 2:** read by the demo adapters and by every future host. **If wrong:** a fabricated exit code becomes
governed evidence that a test passed.

**PROOF, each limb its own observed red:** refusing runner returns **no `exitCode` field at all** (not zero);
in-memory workspace + real runner is refused naming the materialization; containment refuses `../`,
`a/../../`, absolute and drive-qualified paths; a purged read returns `undefined` from `readFile` while `list`
still explains the entry. ⛔ **Rule 7 applies: every exported value here lands with its mutant.**

## 4. Phase 2 · The host lifecycle — and a `cwd` that currently points at the server

⭐ **THE MECHANICS PASS FOUND A HAZARD THE DESIGN DID NOT NAME.** The only seam through which a `cwd` could reach
the executing model is **zero-argument** — `OpenProducerSession = () => Promise<ProducerSession>` — and
`openPiExecutionSession` hardcodes `process.cwd()` twice. ⛔ **A sandboxed step therefore runs in the SvelteKit
server's own working directory until that signature chain takes a parameter.** This is a containment defect, not
plumbing, and it lands here rather than in Phase 3.

**AND THERE IS NOWHERE TO HANG AN UNDERTAKING-SCOPED RESOURCE.** Measured: no `hooks.server.ts`, no `locals`, no
`+layout.server.ts`; `grep "locals"` over the app returns **0**. The entire mutable process state of the server
tree is **five `let` declarations, all in `workbench.ts`**. Every shared resource is an exported getter.

**DO:** follow the `JPWB_DEMO_DB` precedent exactly rather than inventing a pattern —
**one durable root from one env key, one subdirectory DERIVED from the owner id, resolved per request.** The
content plane already sets that precedent by derivation (`${DB_PATH}.content.sqlite`), and the artifact store
already puts the owner in the key rather than in the object.

- ⛔ **TEST MODE IGNORES THE ROOT UNCONDITIONALLY**, as `JPWB_DEMO_DB`'s own docblock requires: *"a durable store
  shared across specs would make them order-dependent, which is the failure mode `resetEngine` exists to
  prevent."*
- ⚠ **Read it in the DEFAULT-PARAMETER shape, not the frozen module const.** The frozen shape has a named
  in-repo hazard (`floor-recording.test.ts:19-21`: a plain assignment below the imports is read *after* the const
  froze).
- The owner id is available without changing any action signature: `beginExecute` lacks `params`, but
  `pwu.undertakingId` is on the flattened object, and `listPwus` already keys on that field.

**RULE 2:** read by the workspace adapter and the process runner's `cwd`. **If wrong:** either every phase gets
its own directory (seven fragments, not one product — `R8` violated), or a model runs commands in the server's
source tree.

**PROOF:** a second step, in a new session with a new plan, reads a file the first step wrote — and a
containment test proves the resolved `cwd` is the owner's subdirectory and never the server's.

## 5. Phase 3 · Capability → tools, by absence

**DO:** thread the step's GRANTED capabilities into the session and mint only the authorised tools.
`stepBindingFor` stops hardcoding `[{capability:'network'}]` and requests **per step type**, splitting
capabilities a step **REQUIRES** (ungranted ⇒ refuse the step) from ones it **USES** (ungranted ⇒ do not mint
the tool).

⭐ **This is how RPH-EXE-004's operation-level wording and the code's step-level refusal are reconciled rather
than one being chosen** — an unminted tool degrades the operation, exactly as the rule says.

**RULE 2:** read by every sandboxed step. **If wrong:** a model holds a privilege the binding never granted.

**PROOF (spike-established, to be re-proven as committed tests):** granted `["network"]` only ⇒ step refused,
**0 model calls, 0 exchange records**; granted `file-system` but not process-execution ⇒ `write_file` minted,
`run_command` withheld, **`run_command` calls = 0** with the file still on disk; and exact membership —
`["file"]`, `["file-syste"]`, `["file-system-extra"]`, `["FILE-SYSTEM"]` all mint **nothing**.

## 6. Phase 4 · The observed tool-call record — split at the ratification line

⛔ **§22.1 makes model output untrusted external input, so *"the model said it ran the tests"* is not evidence
that tests ran.** The adapter must report what it OBSERVED. ⚠ `toolCalls()` **does not exist at HEAD** — it is
only on the spike.

**PART A — NO RATIFICATION, LAND FIRST.** `ProducerSession`, `ExchangeRecord`, `CaptureTryInput` and friends are
app- and package-local TypeScript interfaces. Land the observation type and populate it, so the fact exists and
is testable, with the adapter as its source.

**PART B — A RATIFICATION ACT, NAMED AND SEPARATE.** Carrying tool calls onto `MODEL_EXCHANGE` touches a
`z.strictObject` whose object, command and event payloads are **byte-identical by design** and **all three are
GENERATED** — *"do not edit by hand. Regenerate with `bun run gen:objects`"*, source `vocab/m1-object-fields.json`
and `vocab/m3-commands-events.json`. ⛔ **And the `extensions[]` escape hatch is unreachable from the command
surface — driven, and already recorded in `REG-005`.** So there is no back door: it is a vocab change, a
regeneration, and a ratification.

**RULE 2:** read by anyone auditing whether a command actually ran. **If wrong:** the governed record rests on the
model's word.

**PROOF:** a step whose model *claims* a command ran while the adapter observed none must be distinguishable in
the record.

**R6 SETTLES THE LIMB THAT HAD NO ANSWER.** There is no model reasoning in `exitCode: 0` — the producer is

## 11. What this roadmap does NOT do

- ⛔ **It does not touch the authoring plane.** It works live and is the reference, not the subject.
- ⛔ **It does not build `run-tool-step.ts`.** `TOOL_INVOCATION` stays ratified-and-undispatched — a pre-existing

- ⛔ **It does not widen `floor-gate.ts`'s `AI_STEP_TYPES`.** The divergence from `execution-attempts.ts` is

  signal 3 regardless. Widening would overturn a deliberate distinction on the strength of an artificial case.
- ⛔ **It does not add a retention class** to `Purgeability`. `REG-Q-056` is OPEN and that is not this
  programme's question.
- ⛔ **It does not merge `spike/tool-execution`.** The spike proved the seam; it is not the implementation.
