### The three defects, as found

**These are not programme work. They are holes, found, confirmed, and currently open in governed behaviour.**
Each was confirmed against the ENTIRE suite under SOURCE resolution — `bunx vitest run` on the root config, the
resolution `scripts/mutants/run.ts` uses. Baseline **358 files / 3,614 passed**; each mutated run executed the
same 358 and produced **ZERO new failures**. ⚠ Two earlier confirmation attempts were invalid and are recorded in
`DESIGN §7` rather than quietly replaced. All three sit in files coverage rates at **85–100% branches**.

### S0.1 · `BLOCKING_SEVERITIES` can silently lose `CRITICAL`

`packages/rph-assurance/src/assurance-rules.ts`. The set exists so a criterion's ratified `severityIfNotMet` is
answered the SAME way the disposition ladder answers it, instead of each caller re-deciding. Remove `'CRITICAL'`
and an open critical finding stops blocking for `handlers/assurance.ts`, `handlers/reject-authorization.ts` and
`validators.ts`.

**WHAT:** a test that asserts the SET'S CONTENT against the ladder's own behaviour — not a literal copy of the
set, which would be a pin restating the code. ⭑ The assertion must be *"every severity this set contains actually
forces REJECTED through `dispositionFromFindings`, and every severity that forces REJECTED is in the set"* — a
round-trip, so the two cannot drift apart silently. Then the ledger entry, naming that test.

### S0.2 · `canPromoteBaseline` can drop its authority requirement

`packages/rph-domain/src/governance.ts`. RPH-BAS-006 requires an effective, AUTHORITY-BACKED promotion decision.
Delete the `d.authorityHeld` conjunct and a baseline promotes on an unbacked decision.

**WHAT:** a test that promotes with `authorityHeld: false` on an otherwise valid EFFECTIVE `PROMOTE_BASELINE`
decision and asserts `NO_EFFECTIVE_PROMOTION_DECISION`. Then the ledger entry.

### S0.3 · `RphErrorSchema` can be widened from `strictObject` to `object`, and the published contract never notices

`packages/rph-contracts/src/errors.ts`. The schema promises the serialized error carried in `CommandResult.error`
and in event/observation payloads is EXACTLY the declared shape — **closed to unknown keys**. Widening it accepts
untrusted extra fields at a boundary the contract requires to reject them. Consumers: `envelopes.ts`,
`validate.ts`, `gen/schema-manifest.ts`.

⛔ **AND IT REACHES A PUBLISHED ARTIFACT.** `packages/rph-contracts/schemas/objects/RphError.json` is the client
contract, and it carries `additionalProperties`. It is produced by `bun run gen` — ⚠ **which is NOT one of
`gate:fast`'s eleven steps**, so the committed artifact is never regenerated or compared against its source in
the gate. A source-side widening leaves the published schema stale and correct-looking while the code it
describes has stopped enforcing it.

**WHAT:** a test asserting `RphErrorSchema` REJECTS an object carrying an unknown key — the negative that
`strictObject` exists for — plus its positive half. ⭑ **AND a freshness check comparing the generated
`schemas/objects/*.json` against a fresh `gen` run**, because a guard on the zod schema alone leaves the
published-artifact half of the promise still unguarded. ⚠ That check is a candidate `gate:fast` step and is
flagged for `R1`'s S1.3 rather than smuggled in here.

**RULE 2:** consumers are the envelope and validation layers and every external client reading the published JSON
Schema; what breaks if it is wrong is that a boundary declared closed silently accepts extra fields.

⚠ **AND THE NEGATIVE HALF IS REQUIRED IN ALL THREE.** A test that only proves refusal can be satisfied by a guard that
refuses everything — `MU-FRESH-18-B`'s recorded shape. Each needs its own second mutant proving the guard still
ADMITS the authorized case, or it is a control that cannot fail.

**RULE 2 (for `S0.1` and `S0.2`):** the consumers are the assurance and governance handlers; what breaks if these
are wrong is that an open critical finding stops blocking, and an unbacked decision promotes a baseline to
AUTHORITATIVE.

## 2. ✅ PHASE 1 (R1) — COMPLETE. The per-file coverage ratchet

**LANDED 2026-09-12. Five limbs, five mutants, FIVE KILLED — each observed reddening EXACTLY ONE test with the
other four green.** That separation is the whole claim: a per-file mechanism whose limbs fail together cannot
tell a regressed file from a new one, which is the distinction it exists to make.

| limb | mutant | what it alone catches |
| --- | --- | --- |
| RATCHET | `R1-A` slackens the comparison | a file adding uncovered code |
| POPULATION (added) | `R1-B` blinds it to new files | ⭐ a NEW file full of uncovered code — which CANNOT regress against a baseline that never heard of it, so the ratchet limb is structurally silent |
| POPULATION (removed) | `R1-C` blinds it to vanished files | a weak file dropping out of the denominator — the CSAA defect this programme began with |
| BLINDED READER | `R1-D` treats a missing summary as nothing to check | the gate passing precisely when it measured nothing |
| EMPTY POPULATION | `R1-E` accepts a zero-file summary | the same vacuity through a summary that exists and is empty |

### The steps, as planned

### S1.1 · The writer and the derived baseline

`scripts/coverage-floor.ts --write` reads `coverage/coverage-summary.json` and writes
`verif/coverage/per-file-floor.baseline.json`: per file, the UNCOVERED COUNT for each of the four metrics.
Modelled on `scripts/slice-ledger.ts`, whose header records why a committed artifact beats a self-rebuilding one.

⛔ **COUNTS, NOT PERCENTAGES, AND THE DIFFERENCE IS THE POINT.** A percentage floor lets a file add uncovered
branches provided it adds covered ones alongside — the averaging defect reproduced inside one file. A count
ceiling says the thing actually wanted: **you may not add uncovered code.**

**RULE 2:** read by S1.2. If wrong, a file regresses and the gate says nothing.

2. ⛔ **POPULATION** — the baseline's file set must equal the measured file set. A file added or removed without
   a regenerated baseline FAILS. Without this limb a new file with uncovered code is invisible.

⚠ If one mutation trips both, they are one check wearing two names — `REG-F-099`'s shape, checked in S1.4.

## 3. ✅ PHASE 2 (R2) — COMPLETE. Change-scoped mutation

**LANDED 2026-09-12.** `bun run mutants:changed [--run] [--strict] [--range=A..B]`. Five limbs, five mutants,
five KILLED. The intersector's pure core lives in `scripts/mutants/scope-core.ts` precisely so the limbs can be
driven without git, a staged index, or ~4s per mutant.

**THREE OUTCOMES, THREE EXIT CODES, AND THEY ARE NOT ALLOWED TO MERGE:**

| exit | signal | what it means |
| --- | --- | --- |
| 1 | ⛔ BROKEN GUARANTEE | a guard over the changed region SURVIVED — the suite is green and the protection is gone |
| 3 | ⛔ UNGUARDED CHANGE (`--strict`) | nothing has ever tried to break this line |
| 2 | ⛔ INSTRUMENT DID NOT RUN | nothing was measured, so nothing is claimed |

⭐ **THE THIRD OUTCOME WAS NOT IN THE DESIGN. IT WAS FORCED BY RUNNING THE THING.** `run.ts` refuses to mutate a
tree that does not match a stable staged index baseline — which is exactly the state a change-scoped tool is
invoked in. The first implementation read `status !== 0` and announced **BROKEN GUARANTEE about a mutation that
was never applied.** The fix then matched `ABORTED_DIRTY` as a bare substring — and the runner's summary prints
one row per verdict kind, so every HEALTHY run contains the literal `ABORTED_DIRTY 0`, which classified a
genuinely SURVIVED mutant as *"the instrument did not run"* and **suppressed the finding the command exists to
raise.** ⚠ A false positive gets investigated; that false negative is silent. Both are now regression mutants
(`R2-D`, `R2-E`) rather than remembered.

**WHY THE ABSENCE SIGNAL IS ADVISORY BY DEFAULT, AND WHAT FLIPS IT.** 75 of 106 production files carry no guard;
blocking on "you touched an unguarded line" today would demand the whole `R3` obligation before anyone could
land an edit. ⛔ The trigger is NAMED rather than left to drift: when `R3`'s burn-down reaches zero unguarded
production-consumed exports, `--strict` becomes the default.

⛔ **IT IS NOT A `gate:fast` STEP.** The gate runs on a tree whose changes are committed, where `git diff HEAD`
is empty and this command has nothing to say. It belongs in the EDIT loop. `gate:fast` stays at 12 steps.

### The steps, as planned

**The basis the sponsor asked for:** for the region a diff touches, *is there a declared guard over it, and does
that guard still discriminate after the change?* ⭑ Enabled by a measured fact: **all 238 measurable ledger
entries resolve to an exact `(file, line-range, named-victim)` triple — 238 of 238.**

### S2.1 · The intersector

`scripts/mutants/scope.ts`: given `git diff --unified=0` (worktree, staged, or a named range), return the mutant
ids whose anchor range intersects a changed hunk, and the changed hunks that intersect NO anchor.

**RULE 2:** read by S2.2 and by the agent. ⛔ **If it under-selects, an agent is told "nothing guards this" when
something does — a false all-clear, which is worse than no signal.** So S2.4 proves selection in BOTH directions.

### S2.2 · `bun run mutants:changed`

Feeds the selected ids to the existing runner as argv filters. **No new engine.** Measured cost: ~4s per mutant
(pilot: 16 mutants, 80.9s of subprocess time).

### S2.3 · The two signals, reported distinctly

| signal | meaning |
| --- | --- |
| a guard over the changed region **SURVIVES** | ⛔ **a guarantee was broken** — the test that discriminated no longer does, and the suite is green |
| the changed region has **no declared guard** | ⛔ nothing has ever tried to break this line |

⚠ **THEY MUST NOT SHARE AN EXIT CODE OR A MESSAGE.** One says *you broke something*; the other says *nothing was
watching*. Collapsing them reproduces the defect this programme exists to remove.

| ⛔ feed a diff naming a file not in the ledger | absence signal, never silent success |

⚠ Diff-intersection catches the LOCAL case only. Change `A` and a guard over `A` goes slack — caught. Weaken

attribution JPWB does not collect. ⛔ **The command must SAY this every run.** A guarantee described as catching
what it cannot catch is worse than an absent one.

**TRAP 1 — a mutation inside a file BREAKS THAT FILE'S OWN LEDGER ANCHORS**, so `verif/mutant-ledger.test.ts`
